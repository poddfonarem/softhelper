# Contributing to softhelper

First off, thank you for considering contributing to **softhelper**! It's people like you who make open-source tools better for everyone.

To ensure a smooth collaboration, please take a moment to review the following guidelines.

## How Can I Contribute?

### Reporting Bugs
If you find a bug, please open an **Issue** and include:
* A clear and descriptive title.
* Steps to reproduce the problem.
* Your operating system and environment details.
* Any relevant logs or error messages.

### Suggesting Enhancements
Have an idea for a new feature? We'd love to hear it! 
* Check if a similar suggestion already exists in the Issues.
* Explain why this feature would be useful to most users.

### Pull Requests (PRs)
1. **Fork the repository** and create your branch from `main`.
2. **Write clean code**: Follow the existing style and naming conventions of the scripts.
3. **Document your changes**: Update the README or add comments if you introduce new logic.
4. **Test your code**: Ensure the script works as expected and doesn't break existing functionality.
5. **Open a PR**: Provide a clear description of what you've changed and why.

## Style Guidelines
* **Shell Scripts**: If you're writing bash/sh, please use `shellcheck` to find common errors.
* **Clarity**: Keep scripts simple and modular. Avoid over-complicating logic for simple tasks.
* **Security**: Never hardcode credentials or sensitive data.

## Code of Conduct
By participating in this project, you agree to maintain a respectful and inclusive environment. Please be kind to other contributors!
